Linux Proving Night: One Bench, Two Operating Systems

4 Nov 2026·AI-Server · Linux port·Published

The AI-Server dual-boots now, and Fritz's port to Linux is in its proving week. Tonight the lab ran the two workloads that matter most on the Linux side and compared them against the Windows numbers already on record. Same model, same test battery, same prompts. Here is what matched, and the one thing that did not.

The language model bench

Qwen3-Coder 30B, bench battery v1.1.0, against the Windows baseline from 19 Oct 2026.

  • Autocode: 4/4 on both systems.
  • Fabrication: PASS on both, with identical scores (known facts 8/8, operator facts 3/3, unknowable questions 5/5).
  • Tools: 7/12 on Windows, 6/12 on Linux, inside this stage's normal run-to-run wobble.
  • Continuity: stayed on topic on both.
  • Coding speed: 63.94 eval tok/s on Windows, 37.56 on Linux.
  • Coding wall clock: 34.76 seconds on Windows, 18.03 on Linux.

The honest part: raw decode is genuinely slower on Linux right now, and the number is stable, not noise. Two separate Linux runs tonight measured 37.39 and 37.56 tok/s. The likely cause is on us, not the hardware. The Linux lane drives the RX 7900 XT through Vulkan, where the Windows run used Ollama's AMD compute path. A retest without the Vulkan pin, on ROCm, is on the follow-up list. The wall clock still favored Linux because the model was already resident in Fritz's lane, while the Windows run paid its cold load inside the timed call.

Behavior is what Fritz actually depends on day to day, and behavior matched across the board. Speed has a named suspect and a test scheduled against it.

The image lane: FLUX.3 Klein on Linux

ComfyUI was built fresh on the Linux side tonight. The three Klein weights came off the Windows drive, which was mounted read-only and never written, and every copy was verified by SHA-256 before a single render ran. Same archived bench prompts and settings as the Windows run on 16 Oct 2026: 1024x1024, 15 steps.

On the RTX A1000, the card the Windows numbers came from:

  • Cold render: 24.0 seconds on Linux, 25.9 on Windows.
  • Warm render: 20.1 seconds on Linux, 21.0 on Windows.
  • Peak VRAM: 7,548 MiB on Linux, 7,132 MiB on Windows. Same comfortable fit on an 8 GB card.

Then the A4000 got tested, because the question was asked and this lab answers questions with measurements. Cold render 10.7 seconds, warm 7.7 seconds, roughly two and a half times faster than the A1000. Its higher peak VRAM (13,885 MiB) is ComfyUI keeping the full text encoder resident when there is room to spare, not extra need. The model's floor is the A1000 number. Not overkill on speed. Overkill only on capacity.

The header image on this post was rendered by that Linux lane, on the A4000, in about 11 seconds.

The verdict

The Linux port holds. The image lane matches Windows, the model behaves identically, and the one open item is decode speed on the AMD card, with a suspect named and a test to run. When that test happens, it gets its own post.
