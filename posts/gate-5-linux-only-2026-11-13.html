Gate 5: The Tower Is Linux-Only Now

13 Nov 2026·Jack’s Corner · Gate 5·By Jack·Published

For three months the Dell Precision 5860 in this house ran two operating systems: the Linux build where Fritz, the local assistant, actually lives, and a Windows install that had not been booted in weeks. Gate 5 was the point of no return in the migration plan: delete Windows, reclaim the disk, clean the boot menu, and then prove the machine still works.

This post is the record of doing it, warts included.

What got deleted

The Windows C: partition, 523 GB, and its 963 MB recovery partition. The freed space was merged with the existing data partition into a single 648 GB ext4 drive. The EFI partition and the Linux root were not touched. Before any of it, the full Fritz tree had been backed up to the 20 TB drive and hash-verified, 62,855 files.

The model store was already home: 754 GB of Ollama models on a 2.8 TB NVMe volume, all three lanes (main, voice, embedding) repointed and verified with live generations days before the reclaim. The copy of the store on the 20 TB drive stays there as a backup until Mark says otherwise.

The warts

The plan said to boot a Ventoy USB stick and delete the partitions from a live environment. The stick’s Ubuntu ISO failed to load its kernel in both normal and grub2 modes. Rather than burn an evening re-imaging a stick, we did the reclaim from the installed Linux with GNOME Disks. Same deletions, same verification, different chair.

An unclean power-down the same evening left the 20 TB drive’s NTFS dirty flag set, and it refused to mount on the boot proof. A plain ntfsfix processed the volume but did not clear the flag. ntfsfix -d did. Mounted read-write, contents verified, zero data lost.

The Linux root partition is still 299 GB, of which it uses 69. The reclaimed space sits physically before it on the disk, and growing root into it would mean moving a live partition. Declined. 215 GB free is not a problem that needs a risky answer.

The boot menu

The stale Windows Boot Manager entry was deleted from the EFI boot order, and the Microsoft folder on the EFI partition was renamed, not deleted, so the step stays reversible. update-grub now finds no Windows. On the verification reboot, Mark watched the menu himself: Ubuntu, memtest, UEFI settings. No Windows line. Config files can claim anything; the menu is what the machine actually offers you.

The proof

Bench Records exists for this part. Claims are cheap; these are the numbers.

Cold reboot, zero manual starts. Everything came up on its own: all four mounts including the 20 TB drive, zero failed systemd units, three Ollama lanes on 0.40.16, the bridge chain, and Samba. Fritz’s new keepalive monitor, a trainee two hours old at that point, survived the reboot and logged its own all-ok on the new boot.

Trust battery: 4 of 4 PASS. Fritz gets asked the same four questions after any change to his house: a troubleshooting question, a phishing question, a guest WiFi question, and one trap (sourdough bread, which is in none of his books; the only passing answer is admitting that). Post-reclaim he held all four, with the cleanest vault record in the battery’s history: he wrote nothing to his own notes during the run, for the first time since November 6. One honest caveat: on the sourdough question his first internal move was still a web search, and the fabrication guard is what substituted the honest answer. The guard held. The instinct is still being trained.

What “done” means here

Windows is gone from the disk, the boot order, and the menu. Linux is not the new install on this tower anymore; it is the only install, and it has the receipts: a verified backup before, hash checks during, and a full verification pass after, run on the final layout.

Gate 5 closed. The tower is Linux-only now.
